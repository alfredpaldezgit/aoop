Project Title: PHP Inventory Management System

Description:
A comprehensive, web-based Inventory Management System built with PHP, MySQL, 
and Bootstrap 5, following the Model-View-Controller (MVC) architectural pattern.

with advanced features including user authentication, detailed reporting,

businesses, offering features such as product categorization, stock management, 
user authentication with role-based access control, comprehensive reporting tools, 
and analytics capabilities including ABC analysis for inventory optimization.

Key Business Value:
- Streamline inventory management operations
- Provide real-time visibility into stock levels
- Generate actionable business intelligence through analytics
- Secure multi-user access with role-based permissions
- Reduce manual inventory tracking and reporting effort

6.1 ARCHITECTURAL PATTERN
-----------
The system follows the Model-View-Controller (MVC) pattern:

┌─────────────────────────────────────────────┐
│          USER INTERFACE (View)              │
│        (HTML, CSS, JavaScript)              │
└─────────────────────────────────────────────┘
              ↓              ↑
┌─────────────────────────────────────────────┐
│      CONTROLLER (Request Handler)           │
│   (InventoryController, AuthController)     │
└─────────────────────────────────────────────┘
              ↓              ↑
┌─────────────────────────────────────────────┐
│     MODEL (Business Logic & Data)           │
│  (Product, Category, User, Stats models)    │
└─────────────────────────────────────────────┘
              ↓              ↑
┌─────────────────────────────────────────────┐
│      DATABASE (MySQL Data Storage)          │
└─────────────────────────────────────────────┘

Benefits:
- Separation of concerns
- Easier to test and maintain
- Code reusability
- Better scalability
- Clear responsibility division

6.2 CLASS DIAGRAM (Simplified)
-----------
User
├─ id: int
├─ username: string
├─ email: string
├─ password: string (hashed)
├─ role: enum(admin, staff, viewer)
├─ status: enum(active, inactive)
└─ Methods: authenticate(), updateProfile(), changePassword()

Product
├─ id: int
├─ name: string
├─ description: text
├─ quantity: int
├─ price: decimal
├─ category_id: int (FK)
├─ image: string
└─ Methods: create(), read(), update(), delete(), getLowStock()

Category
├─ id: int
├─ name: string
├─ description: text
└─ Methods: getAllCategories(), getCategoryById()

Stats
├─ Methods: getTotalProducts(), getTotalValue(), getLowStockCount()
└─ Methods: getTopProducts(), getCategoryBreakdown()

6.3 DATA FLOW DIAGRAM
-----------
User Input → Validation → Controller → Model → Database → Processing → View

Example Flow for Creating Product:
1. User fills product form in View
2. Form data sent to Controller (CREATE action)
3. Controller validates input via SecurityHelper
4. Validated data passed to Product Model
5. Model executes INSERT query with prepared statement
6. Database stores product record
7. Success/Error response sent back to Controller
8. View updated with result message

6.4 DESIGN PATTERNS USED
-----------

1. Model-View-Controller (MVC) Pattern
   - Separates data, presentation, and business logic
   - Location: app/ directory structure

2. Active Record Pattern (in Models)
   - Database tables mapped to classes
   - Models handle both data and operations
   - Location: app/models/ directory

3. Front Controller Pattern
   - Single entry point (index.php)
   - Routes requests to appropriate controller
   - Location: index.php

4. Service Locator Pattern
   - Centralized configuration and helpers
   - Location: config/ and helpers/ directories

5. Singleton Pattern
   - Database connection management
   - Single PDO instance throughout application

6.5 SYSTEM FLOW DIAGRAMS

LOGIN FLOW:
User → Login Page → Verify Credentials → Check Role → Dashboard/Inventory

PRODUCT CREATION FLOW:
User → Click Add → Form Validation → Save to DB → Refresh List → Display

REPORT GENERATION FLOW:

8.4 TROUBLESHOOTING COMMON ISSUES
-----------

ISSUE: "Database Connection Failed" Error
Symptoms: Cannot access application, database error message
Solutions:
- Check MySQL is running in XAMPP (green indicator)
- Verify credentials in config/database.php match XAMPP settings
- Ensure database was created by running setup script
- Check if port 3306 is available (not blocked)
- Try restarting MySQL service
- Run setup script again to reinitialize database

ISSUE: Login Always Fails
Symptoms: Cannot login with any credentials, including default admin
Solutions:
- Clear browser cache and cookies
- Try logging in with default credentials: admin / admin123
- Check if admin user exists in database
- Verify password hashing is working (BCrypt)
- Create a new test user and try logging in
- Check browser console for JavaScript errors

ISSUE: Images Not Uploading
Symptoms: Product images don't upload, get stuck or error
Solutions:
- Ensure directory exists: public/uploads/images/
- Set folder permissions to 755 (writable)
- Check PHP upload_max_filesize in php.ini
- Verify file types are allowed (JPG, PNG, GIF)
- Check available disk space
- Review web server error logs

ISSUE: Slow Performance / Timeout
Symptoms: Pages load slowly, operations timeout
Solutions:
- Check server resources (CPU, RAM usage)
- Optimize database queries
- Clear browser cache
- Restart Apache/MySQL services
- Check network connection
- Reduce number of products for large inventories

ISSUE: Port 3306 Already in Use
Symptoms: MySQL won't start, error about port
Solutions:
- Check if another MySQL instance is running
- Stop competing MySQL service
- Change XAMPP MySQL port in config
- Check firewall settings blocking port
- Restart computer if processes won't terminate

/**
 * Product Model - Handles all product-related database operations
 *
 * This class manages product data including creation, retrieval, updating,
 * and deletion. It implements CRUD operations and provides additional
 * methods for inventory analysis and reporting.
 *
 * @package Models
 * @version 2.0
 * @author [Author Name]
 */
class Product {
    private $pdo;
    private $table = 'products';
    
    /**
     * Initialize Product model with database connection
     *
     * @param PDO $pdo Database connection object
     */
    public function __construct($pdo) {
        $this->pdo = $pdo;
    }
    
    /**
     * Create a new product record in the database
     *
     * Creates a new product with provided data including name, description,
     * quantity, price, category, and optional image.
     *
     * @param array $data Product data array with keys:
     *                     - name: (string) Product name [REQUIRED]
     *                     - description: (string) Product description
     *                     - quantity: (int) Stock quantity [REQUIRED]
     *                     - price: (float) Product price [REQUIRED]
     *                     - category_id: (int) Category ID [REQUIRED]
     *                     - image: (string) Image filename
     *
     * @return int Product ID of newly created product
     * @throws PDOException If database operation fails
     * @throws InvalidArgumentException If required fields missing
     *
     * @example
     * $productData = [
     *     'name' => 'Laptop Pro',
     *     'quantity' => 10,
     *     'price' => 1200.50,
     *     'category_id' => 1
     * ];
     * $productId = $product->create($productData);
     */
    public function create($data) {
        try {
            $query = "INSERT INTO {$this->table} (name, description, quantity, price, category_id, image) 
                     VALUES (?, ?, ?, ?, ?, ?)";
            $stmt = $this->pdo->prepare($query);
            
            $stmt->execute([
                $data['name'],
                $data['description'] ?? null,
                $data['quantity'],
                $data['price'],
                $data['category_id'],
                $data['image'] ?? null
            ]);
            
            return $this->pdo->lastInsertId();
        } catch (PDOException $e) {
            throw new PDOException("Failed to create product: " . $e->getMessage());
        }
    }
}

/**
 * Calculate total inventory value with category breakdown
 */
public function getTotalInventoryValue() {
    // Query to sum all product values (quantity * price)
    $query = "SELECT 
                c.id,
                c.name,
                SUM(p.quantity * p.price) as category_value,
                COUNT(p.id) as product_count
              FROM categories c
              LEFT JOIN products p ON c.id = p.category_id
              GROUP BY c.id, c.name
              ORDER BY category_value DESC";
    
    try {
        // Prepare and execute query safely
        $stmt = $this->pdo->query($query);
        $results = $stmt->fetchAll(PDO::FETCH_ASSOC);
        
        // Calculate grand total
        $totalValue = array_sum(array_column($results, 'category_value'));
        
        return [
            'total' => $totalValue,
            'by_category' => $results
        ];
    } catch (PDOException $e) {
        // Log error and throw exception
        error_log("Database error: " . $e->getMessage());
        throw new PDOException("Failed to calculate inventory value");
    }
}

12.1 AUTHENTICATION SECURITY
-----------

Password Storage:
- Algorithm: BCrypt (hash algorithm with salt)
- Cost Factor: 10 (slowing factor)
- Hash Output: 60 characters
- Saltiness: Automatically generated and included in hash
- Verification: password_verify() function

Example Hash:
Plain Password: "admin123"
BCrypt Hash: "$2y$10$qMN2wc3qTvXbQGPnGjpYeOoHzjCY3n4b6yDqZm5zVxQ1N8a8pVl0O"

Code Implementation:
// Hashing
$hashedPassword = password_hash($plainPassword, PASSWORD_BCRYPT, ['cost' => 10]);

// Verification
if (password_verify($plainPassword, $hashedPassword)) {
    // Password correct
} else {
    // Password incorrect
}

Session Management:
- Session ID: Randomly generated, 32+ character string
- Session Timeout: Configurable (default: 30 minutes)
- Secure Flag: Set for HTTPS connections
- HttpOnly Flag: Prevents JavaScript access
- SameSite: Set to 'Strict' for CSRF protection

12.2 SQL INJECTION PREVENTION
-----------

Vulnerable Code (DO NOT USE):
$username = $_POST['username'];
$query = "SELECT * FROM users WHERE username = '$username'";
// Attacker input: ' OR '1'='1
// Result: Returns all users

Protected Code (CORRECT):
$username = $_POST['username'];
$query = "SELECT * FROM users WHERE username = ?";
$stmt = $pdo->prepare($query);
$stmt->execute([$username]);
$user = $stmt->fetch();

Implementation Methods:
1. Prepared Statements (PRIMARY)
   - Separate SQL from data
   - Parameters bound safely
   - Works with all databases
   
2. Parameterized Queries
   - Placeholders (?) for values
   - Executed with execute() method

3. Input Validation (SECONDARY)
   - Validate data type
   - Validate data format
   - Validate data length
   - Reject invalid input

12.3 XSS (CROSS-SITE SCRIPTING) PREVENTION
-----------

Vulnerable Code (DO NOT USE):
echo "Welcome " . $_GET['username']; // Direct output
// Attacker input: <script>alert('xss')</script>

Protected Code (CORRECT):
echo "Welcome " . htmlspecialchars($_GET['username'], ENT_QUOTES, 'UTF-8');
// Output: Welcome &lt;script&gt;alert('xss')&lt;/script&gt;

Protection Techniques:

1. Output Encoding
   - htmlspecialchars(): Convert special chars to HTML entities
   - htmlentities(): Encode all special characters
   - json_encode(): For JSON output

2. Content Security Policy (CSP)
   Header: Content-Security-Policy: default-src 'self'
   - Prevents inline scripts
   - Restricts external resources
   - Reports violations

3. Input Validation
   - Validate data type
   - Reject dangerous characters
   - Whitelist approach (only allow safe characters)

Example Implementation:
$userName = htmlspecialchars($_POST['username'], ENT_QUOTES, 'UTF-8');
echo "User: " . $userName; // Safe output

12.4 CSRF (CROSS-SITE REQUEST FORGERY) PREVENTION
-----------

Attack Scenario:
1. User logs into application
2. User visits malicious website (in another tab)
3. Malicious site sends hidden request to application
4. Request executes with user's authentication
5. User's data modified without consent

Prevention: CSRF Tokens

Token Generation:
$_SESSION['csrf_token'] = bin2hex(random_bytes(32));

Token Verification:
if (!isset($_POST['csrf_token']) || $_POST['csrf_token'] !== $_SESSION['csrf_token']) {
    die('CSRF token validation failed');
}

Form Implementation:
<form method="POST">
    <input type="hidden" name="csrf_token" value="<?php echo $_SESSION['csrf_token']; ?>">
    <input type="text" name="username">
    <button type="submit">Submit</button>
</form>

12.5 INPUT VALIDATION
-----------

Validation Types:

1. Type Validation
   - Check data type (int, string, float, bool)
   - filter_var($value, FILTER_VALIDATE_INT)

2. Format Validation
   - Email format: filter_var($email, FILTER_VALIDATE_EMAIL)
   - URL format: filter_var($url, FILTER_VALIDATE_URL)
   - IP address: filter_var($ip, FILTER_VALIDATE_IP)

3. Range Validation
   - Numeric range: value >= min && value <= max
   - String length: strlen($str) >= min && strlen($str) <= max

4. Pattern Validation
   - Regular expressions for complex patterns
   - Phone: /^\d{3}-\d{3}-\d{4}$/
   - Username: /^[a-zA-Z0-9_]{3,20}$/

5. Custom Validation
   - Database lookups (user exists?)
   - Business logic checks

Implementation Example:
function validateProductData($data) {
    $errors = [];
    
    // Name validation
    if (empty($data['name'])) {
        $errors[] = "Product name required";
    } elseif (strlen($data['name']) > 255) {
        $errors[] = "Product name too long";
    }
    
    // Quantity validation
    if (!is_numeric($data['quantity'])) {
        $errors[] = "Quantity must be numeric";
    } elseif ($data['quantity'] < 0) {
        $errors[] = "Quantity cannot be negative";
    }
    
    // Price validation
    if (!is_numeric($data['price'])) {
        $errors[] = "Price must be numeric";
    } elseif ($data['price'] < 0) {
        $errors[] = "Price cannot be negative";
    }
    
    return count($errors) > 0 ? $errors : true;
}

12.6 DATA ENCRYPTION
-----------

Sensitive Data Handling:

1. Passwords
   - Never store plain text
   - Use BCrypt hashing
   - Irreversible (one-way function)

2. Email Addresses
   - Store as plain text in database
   - Use HTTPS for transmission
   - Validate before storage

3. Session Data
   - Encrypted in transit (HTTPS)
   - HttpOnly flag (no JavaScript access)
   - SameSite flag (CSRF protection)

4. File Uploads
   - Rename uploaded files (avoid path traversal)
   - Store outside web root
   - Validate file type
   - Scan for malware

HTTPS/SSL Implementation:
- Use HTTPS for all connections
- Install SSL certificate
- Redirect HTTP to HTTPS
- Set Secure flag on cookies
- Set STS (Strict-Transport-Security) header

12.7 SECURITY HEADERS
-----------

Recommended Security Headers:

Header: Content-Security-Policy
Purpose: Prevent XSS attacks
Value: default-src 'self'; script-src 'self' cdn.example.com

Header: X-Frame-Options
Purpose: Prevent clickjacking
Value: SAMEORIGIN (allow framing from same origin only)

Header: X-Content-Type-Options
Purpose: Prevent MIME type sniffing
Value: nosniff

Header: Strict-Transport-Security
Purpose: Force HTTPS connection
Value: max-age=31536000; includeSubDomains

Implementation:
header("Content-Security-Policy: default-src 'self'");
header("X-Frame-Options: SAMEORIGIN");
header("X-Content-Type-Options: nosniff");

12.8 RATE LIMITING
-----------

Purpose: Prevent brute force attacks on login

Implementation:
Track failed login attempts per IP address:
- 3 failed attempts → 5 minute lockout
- 10 failed attempts → 1 hour lockout
- 20 failed attempts → 24 hour lockout

Code Example:
function checkRateLimit($ip) {
    // Check failed attempts in last hour
    $attempts = getFailedAttempts($ip);
    
    if ($attempts >= 5) {
        return false; // Too many attempts
    }
    return true; // OK to proceed
}

14.3 GLOSSARY

AJAX (Asynchronous JavaScript and XML)
- Technology for making asynchronous HTTP requests without page reload
- Enables smooth user experience with background data loading

API (Application Programming Interface)
- Set of rules and protocols for building application software
- Defines methods for communication between components

Audit Log
- Record of all system changes for compliance and security tracking
- Includes user, action, timestamp, and affected data

BCrypt
- Password hashing algorithm using salt and multiple iterations
- Designed to be slow and resistant to brute-force attacks

CRUD (Create, Read, Update, Delete)
- Four basic operations for database records
- Foundation of data manipulation

CSRF (Cross-Site Request Forgery)
- Security vulnerability where attacker makes victim's browser send unwanted requests
- Prevented with CSRF tokens

CSS (Cascading Style Sheets)
- Language for styling HTML elements
- Controls visual presentation of web pages

Database Index
- Data structure for faster data retrieval
- Similar to book index for quick reference

Domain
- Address where web application is hosted
- Example: http://localhost/aoop

Entity Relationship Diagram (ERD)
- Visual representation of database structure and relationships
- Shows tables, columns, and connections

Foreign Key (FK)
- Column that references primary key of another table
- Enforces referential integrity

HTML (HyperText Markup Language)
- Markup language for creating web page structure
- Tags define content and layout

HTTPS (Secure HTTP)
- Encrypted version of HTTP protocol
- Uses SSL/TLS for secure communication

JavaScript
- Programming language for client-side web interactions
- Enables dynamic and interactive web pages

JSON (JavaScript Object Notation)
- Lightweight data format for data exchange
- Human-readable text format for data

MVC (Model-View-Controller)
- Architectural pattern separating concerns
- Model: data, View: presentation, Controller: logic

MySQL
- Relational database management system
- Stores and retrieves structured data

OOP (Object-Oriented Programming)
- Programming paradigm using objects and classes
- Emphasizes modularity and code reuse

PDO (PHP Data Objects)
- PHP database abstraction layer
- Provides unified interface for different databases

Prepared Statement
- Pre-compiled SQL statement with placeholders
- Prevents SQL injection attacks

Primary Key (PK)
- Unique identifier for database record
- Must be unique and not null

Query
- Request for data retrieval or modification
- Written in SQL language

Refactoring
- Restructuring code without changing functionality
- Improves readability and maintainability

SQL (Structured Query Language)
- Language for managing relational databases
- Standard for database operations

SSL/TLS (Secure Sockets Layer / Transport Layer Security)
- Protocols for secure communication over network
- Encrypts data in transit

XSS (Cross-Site Scripting)
- Security vulnerability where attacker injects malicious scripts
- Prevented with output encoding and input validation
